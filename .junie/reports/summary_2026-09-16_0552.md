## Input Prompt & Understanding

### User Request
> "I'd like an additional tool added to the toolbox in this project. Esri's imagery has multiple dates involved. There's the date of the service, and then the date of the imagery within the service. Esri's Wayback app (https://github.com/Esri/wayback) offers to filter available images only to the versions of the basemap with local changes. That would be very helpful. I'd like to make a tool that offers that *and* goes one step further by listing the dates of the captured images instead of the basemap dates. I think this may need to be a two step process:
> 1. identify from the current viewport which service dates have local changes, using a similar approach to what Esri does in their Wayback app. Then,
> 2. Query the endpoint for each of those services to get the popup information that includes the imagery provider, the date, and the ground accuracy. Those may be able to be pulled out as structured data, or as unstructured text
> 
> After that, I'd like a dropdown to select an image date that primarily indicates the date of capture and in parentheses indicates which wayback map version it is. I'd like the tool to also have a checkbox to add all of the listed services to the map as separate layers, named in the same way as in the dropdown.
> 
> It would be appropriate to also only enable this tool at local scales (maybe 1:24000 or less? Possibly even 1:10000) to reduce the chance that the dates aren't representative of the entire image."

### Interpretation & Requirements
1. **Local Change Detection**: Convert active viewport coordinates (WGS 84 center lat/lon) to Web Mercator tile coordinates and query Esri's Wayback tilemap REST endpoint (`/tilemap/{releaseNum}/{level}/{row}/{col}`) backwards through time, deduplicating releases that share identical tile signatures.
2. **True Capture Date Resolution**: Query each changed release's MapServer metadata `identify` endpoint to resolve the exact ground acquisition date (`SRC_DATE2` / `SRC_DATE`), provider attribution (`NICE_DESC` / `NICE_NAME`), ground accuracy (`SRC_ACC`), and resolution (`SRC_RES`).
3. **Dropdown Labeling**: Present entries formatted as `YYYY-MM-DD (Wayback YYYY-MM-DD - Provider)` (e.g. `2022-04-12 (Wayback 2022-05-18 - Maxar)`).
4. **Scale Guard**: Implement a user-configurable maximum scale threshold (default 1:24,000) that verifies current map scale before querying, protecting against date ambiguity at regional/global scales.
5. **Execution Modes**: Single layer update or batch layer addition of all detected local changes as standalone layers in the active map.

## Actions Taken & Code Generated

### 1. Data Models (`wayback_addin/models.py`)
- Added `LocalChangeImageryRelease` dataclass containing `release: WaybackRelease`, `capture_date`, `provider`, `accuracy`, `resolution`, `source`, and property `formatted_display_name` formatting items as `YYYY-MM-DD (Wayback YYYY-MM-DD - Provider)`.
- Implemented `to_dict()` and `from_dict()` serialization.

### 2. Change Detection Engine (`wayback_addin/change_detector.py`)
- Created coordinate math functions: `lon_to_tile_x`, `lat_to_tile_y`, `scale_to_zoom_level`.
- Implemented `fetch_tilemap(release_number, zoom, row, col)` for querying the Esri Wayback tilemap REST API.
- Implemented `get_releases_with_local_changes(lon, lat, zoom, releases, cache_manager)` for detecting changed tiles and filtering out duplicate basemaps.
- Implemented `get_local_changes_with_metadata(lon, lat, scale, max_scale, releases, cache_manager)` combining tilemap change scanning and metadata resolution.

### 3. Map Manager & Cache Enhancements (`wayback_addin/map_manager.py` & `wayback_addin/cache.py`)
- Added in-memory tilemap change result caching (`get_cached_tilemap_changes`, `set_cached_tilemap_changes`) keyed by spatial tile coordinates.
- Implemented `get_map_view_center_and_scale()` to extract active viewport camera coordinates and scale.
- Implemented `add_wayback_layer_as_separate()` and `add_all_local_change_layers()` to create standalone layers with formatted names.
- Updated `WAYBACK_ANY_LAYER_REGEX` to match capture date formatted layers.

### 4. Geoprocessing Tool Implementation (`WaybackImagery.pyt`)
- Added `WaybackCaptureDateTool` to `WaybackImagery.pyt` and registered it in `Toolbox.tools`.
- Implemented `getParameterInfo()`, `updateParameters()`, `updateMessages()`, and `execute()` supporting:
  - Target map selection
  - Configurable maximum scale threshold (default 1:24,000)
  - Dynamic dropdown of local change capture dates
  - Add All Listed Releases as Separate Layers checkbox
  - Output summary text of acquisition details
- Created toolbox documentation XML `WaybackImagery.WaybackCaptureDateTool.pyt.xml`.
