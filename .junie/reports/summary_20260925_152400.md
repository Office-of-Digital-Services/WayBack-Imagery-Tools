## 2. Root Cause Analysis Findings

1. **Metadata Service URL Zero-Padding Bug**:
   - In `wayback_addin/models.py`, `metadata_service_url` stripped leading zeros from release sequence numbers (`WB_2026_R07` -> `r7`).
   - On Esri's servers, `World_Imagery_Metadata_2026_r7/MapServer` is an empty dummy service with 0 layers. The active metadata service is `World_Imagery_Metadata_2026_r07/MapServer`, which contains 14 resolution sublayers.
2. **WMTS Default Capabilities URL 404**:
   - `DEFAULT_WMTS_URL` in `wmts_parser.py` was missing `1.0.0/WMTSCapabilities.xml`, resulting in HTTP 404 when requested without a valid path.
3. **Sublayer Resolution Mapping**:
   - The Wayback metadata services host 14 distinct sublayers (0 to 13) corresponding to ground resolutions from 1.9 cm (zoom 23) down to 150 m (zoom 10).
   - In Esri's `wayback-core`, the sublayer ID is calculated as:
     $$\text{layerId} = \max(0, \min(13, 23 - \text{zoom}))$$
   - Point queries against `/MapServer/{layerId}/query` with `spatialRel=esriSpatialRelIntersects` return high-precision capture dates and provider attribution.

## 3. Architecture & Recommendations

A **Unified Hybrid Architecture** was established:
- **Catalog Discovery**: Use `waybackconfig.json` from S3 as the primary catalog source (faster, smaller ~68KB payload, authoritative item IDs, and direct metadata URLs) with automatic fallback to `WMTSCapabilities.xml`.
- **Metadata Queries & Tilemap Change Detection**: Use ArcGIS Server REST endpoints (`/MapServer/{layerId}/query` with fallback to `/identify`, and `/MapServer/tilemap/...`).
- **Map Layer Rendering**: Retain the CIM WMTS connection layer for the active map display, as it enables instant, sub-millisecond timeline slider and stepper scrubbing without layer recreation.
